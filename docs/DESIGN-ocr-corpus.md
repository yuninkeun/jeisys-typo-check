# 설계: OCR 문구 DB(코퍼스) 기반 오타 검증

- 작성: 2026-11-19 · 상태: 설계안(구현 전)
- 관련: [PLAN.md](../PLAN.md) · [PRD.md](../PRD.md) · 시제품 `scripts/ocr-compare/` · 웹 비교 로직 `lib/ocr-compare.ts`

## 0. 한 줄 요약

**OCR로 한 번 읽어 DB에 쌓고 → 쌓인 문구에서 "기준 표기"를 뽑고 → 새 파일은 기준과 비교한다.**
AI는 마지막 확인용으로만(선택) 쓴다. 크레딧이 없어도 검사가 돌아가고, 파일이 쌓일수록 정확해진다.

## 1. 왜 바꾸나 (지금 구조의 문제)

| 지금 | 문제 |
|---|---|
| 글자가 DB에 쌓이는 길은 AI 검사(`text_extractions`)뿐 | 크레딧이 없으면 아무것도 쌓이지 않는다. 지금 쌓인 건 박스 80여 개 |
| OCR 비교는 고른 파일끼리만, 결과는 화면에만 | 매번 처음부터 읽는다(1개 8초). 파일 1개만 검사하면 비교 대상이 없다 |
| AI 판정이 파일 전체 단위 | 메모·날짜 형식 차이 같은 잡음이 많고 진짜 오타를 놓쳤다(시제품 비교 결과) |

시제품(702개)에서 확인한 사실: **"여러 파일에서 다수가 쓰는 표기와 한 글자 다르다"는 규칙만으로
AI가 놓친 진짜 오타 4종류(Jeieys, Gamansan-ro, Storge, 대륭테크노타워)를 모두 찾았다.**
이 규칙은 비교 대상이 많을수록 강해진다 → 비교 대상을 DB에 영구히 쌓는다.

## 2. 새 흐름

```
 ① 적재(한 번)            ② 기준 만들기(자동)        ③ 검사(매번, 수 초)          ④ 판정 → 학습
 ─────────────            ──────────────────        ───────────────────         ──────────────
 폴더 열기                 쌓인 줄에서 단어별          새 파일/바뀐 파일만 OCR       담당자: 오타 확정 /
 → 해시로 새 파일만 골라    "몇 개 파일에 나오나"       → 기준 표기와 비교            정상 표기 / OCR 오독
 → 연결 도우미 OCR         집계 → 기준 표기 사전        → 문맥(앞뒤 글자) 확인        → 다음 검사부터 반영
 → 줄 글자+위치 DB 저장                                → 의심 자리 확대 재판독       → 오타 확정은
                                                       → 그림과 함께 보여 줌          Illustrator 자동 수정
                                                                                    (선택) 의심 줄만 AI 확인
```

- **파일 자체는 올리지 않는다.** DB에는 글자·위치만 저장하고, 그림(크롭)은 브라우저가 로컬 파일에서 그린다.
- 같은 파일(내용 해시 `content_hash`)은 어느 PC·어느 폴더에서 열어도 한 번만 읽는다.
- OCR은 연결 도우미(각 PC, Windows OCR)가 한다. 도우미가 없는 PC도 **이미 쌓인 결과는 볼 수 있다**.

## 3. 데이터 모델 (Supabase)

### 3.1 `label_files` — 읽은 파일 1개당 1행
| 컬럼 | 설명 |
|---|---|
| `content_hash` text PK | sha256 — `documents`·`review_decisions`와 같은 값 |
| `file_name`, `file_path` | 처음 읽은 이름·상대 경로(표시용) |
| `category` text | 박스 / 스티커 / 멸균지 / 기타 — 경로·이름에서 자동, 수정 가능 |
| `product` text | 기존 `detectProductFromFilename` 재사용 |
| `page_w`, `page_h` int | OCR 렌더 픽셀 크기 |
| `compact_text` text | 메모 블록을 뺀 전체 글자(소문자·공백 제거) — 문맥 확인용 |
| `ocr_engine` text | `win-ocr-ko@1` — 엔진·규칙이 바뀌면 다시 읽을 대상 판별 |
| `read_by` uuid, `read_at` timestamptz | |
| `is_current` bool | 같은 라벨의 옛 버전이면 false (기준 집계에서 가중치 낮춤, 3단계) |

### 3.2 `label_lines` — OCR 줄 1개당 1행
| 컬럼 | 설명 |
|---|---|
| `content_hash` FK, `line_index` | PK(content_hash, line_index) |
| `text` | OCR 원문 |
| `bbox` jsonb | {x,y,w,h} 페이지 대비 0~1 |
| `is_memo` bool | 작업 메모 블록(용지·금박·팬톤·날짜·버전) — 비교에서 제외 |

인덱스: `pg_trgm` GIN on `text` (이미 `similar_extracted_texts`에서 쓰는 확장).

### 3.3 `label_terms` — 기준 표기 사전 (자동 집계 + 사람 확정)
| 컬럼 | 설명 |
|---|---|
| `term` text PK | 소문자 키 (`jeisys`, `가마산로`) |
| `spelling` text | 가장 많이 쓴 표기 (`Jeisys`) |
| `file_count` int | 몇 개 파일에 나오나 (현재 버전 파일 기준) |
| `status` text | `auto`(집계) / `approved`(정상 표기로 확정) / `wrong`(오타로 확정) |
| `correct_to` text | `wrong`일 때 바른 표기 (`Jeieys` → `Jeisys`) |
| `note`, `decided_by`, `decided_at` | |

- `auto` 행은 적재가 끝날 때마다 다시 집계한다(RPC `refresh_label_terms()`).
- `approved`/`wrong`은 사람이 정한 것이라 재집계에 지워지지 않는다.
- 회사·주소·브랜드 이름(Jeisys, Gamasan-ro, POTENZA…)은 처음부터 `approved`로 넣는다(시제품의 NAMES 목록).

### 3.4 `finding_decisions` — 의심 1건에 대한 담당자 판정
| 컬럼 | 설명 |
|---|---|
| `content_hash`, `word`, `suggest` | PK — 어느 파일의 어느 의심인지 |
| `decision` | `typo`(오타 확정) / `ok`(정상 표기) / `misread`(OCR 오독) |
| `decided_by`, `decided_at` | |

판정이 사전으로 흘러가는 규칙:
- `ok` → 그 단어를 `label_terms`에 `approved`로 (다른 파일에서도 다시 안 걸림, 예: 브라질향 `Corea`는 승인 시 `note`에 이유).
- `typo` → `wrong` + `correct_to` 로. 같은 오타가 다른 파일에 있으면 문맥 확인 없이 바로 «오타 확정»으로 표시.
- `misread` → (word, suggest) 쌍을 OCR 오독 목록으로. 같은 쌍은 다음부터 «오독으로 걸러냄»에 바로 넣는다(시/사, 외/오 같은 반복 오독 해결).

기존 `review_decisions`(파일 단위 문제없음/수정 필요/보류)는 그대로 둔다. 의심이 모두 판정되면 파일 결정을 자동 제안한다.

## 4. 화면

| 위치 | 바뀌는 것 |
|---|---|
| 폴더 탐색 › 일괄 검토 | «AI 없이 OCR로 비교» → **«OCR로 읽어 DB에 쌓기 + 검사»**. 이미 쌓인 파일은 건너뛰어 «새 파일 N개만 읽음» 표시 |
| 폴더 탐색 › 파일 1개 | **«기준 대비 검사»** 버튼: 쌓여 있으면 즉시(재판독만), 없으면 읽고 쌓은 뒤 검사 |
| 의심 목록 줄마다 | 그림 + [오타 확정] [정상 표기] [OCR 오독] 버튼 |
| 오타 확정이 있는 파일 | 기존 «Illustrator에서 바로 수정»에 `word → correct_to`가 수정 목록으로 들어감 |
| 새 화면 «기준 표기 사전» | 카테고리별 단어·파일 수·상태, 사람이 확정한 것 목록, 적재 현황(카테고리별 파일 수·마지막 적재) |

## 5. 검사 알고리즘 (지금 `lib/ocr-compare.ts`에서 바뀌는 점)

1. 비교 상대 = **고른 파일들 → DB 전체**(같은 카테고리 우선, 없으면 전체).
   단어별 파일 수는 `label_terms.file_count`를 그대로 쓴다.
2. 문맥 확인(앞뒤 3~6글자에 다수 표기가 들어간 파일이 있는가)은 `label_files.compact_text`를
   `ilike '%앞+제안+뒤%'`로 센다 → 서버 액션 1회. (702개 기준 수십 ms)
3. `label_terms.status`와 `finding_decisions` 오독 목록을 먼저 적용한다.
4. 재판독(확대 OCR)은 의심 줄만 → 연결 도우미. 결과를 `finding_decisions`가 없을 때만 임시 판정으로 표시.
5. 계산 위치: 서버 액션(Next.js). 사전·문맥 조회가 DB에 있으니 브라우저로 전체를 내려받지 않는다.

## 6. AI의 역할 (선택, 4단계)

- 파일 전체가 아니라 **의심 줄 텍스트 + 작은 크롭 이미지**만 보내 "오타인가/의도된 표기인가"만 묻는다.
- 비용: 의심 1건 ≈ 수백 토큰 → 702개 전체에서도 수십 건 수준.
- 크레딧이 없으면 이 단계만 건너뛰고 나머지는 그대로 동작한다.
- 기존 «AI 검사»(파일 전체)는 신규 라벨 디자인처럼 비교 대상이 없는 경우용으로 남긴다.

## 7. 단계별 구현

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 1. 적재 | 테이블 3.1·3.2, 서버 액션(해시 목록 조회·줄 저장), 일괄 검토에 «DB에 쌓기» | 박스·스티커·멸균지 702개가 DB에 있고, 다시 실행하면 0개를 읽는다 |
| 2. 기준 대비 검사 | 3.3 + `refresh_label_terms()`, 서버 검사 액션, 파일 1개 «기준 대비 검사» | 시제품의 진짜 오타 7개 파일을 **하나씩** 검사해도 모두 «오타 의심»에 나온다 · 1개 검사 15초 이내 |
| 3. 판정 학습 | 3.4, 판정 버튼, 사전 화면, Illustrator 수정 목록 연동 | 판정한 오독·정상 표기가 다음 검사에서 다시 안 뜬다 · 오타 확정 → 버튼 한 번에 수정본 저장 |
| 4. AI 확인(선택) | 의심 줄만 AI 판정 | 크레딧 충전 후. 없어도 1~3단계는 그대로 |

1~2단계가 핵심이다. 3단계부터 쓸수록 똑똑해진다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| OCR이 같은 글자를 계속 틀림(시↔사, 외↔오) | 확대 재판독 + `misread` 판정이 쌍 단위로 누적되어 다음부터 자동 제외 |
| 오타가 여러 파일에 복사됨 | 시제품 규칙 유지: 다수 표기가 3배 이상이면 2개 파일에 있어도 의심 |
| 모든 파일이 똑같이 틀림 / 한 파일에만 있는 문장 | 이 방식으로는 못 잡음 → 사전 `wrong` 등록, 신규 문장은 AI 검사로 보완 |
| 옛 버전 파일이 집계를 흐림 | `is_current`(같은 품목코드의 최신 파일만 1) — 3단계에서 |
| 외국어(브라질 Corea 등) | 카테고리·언어별 집계 + `approved` 메모 |
| 연결 도우미가 없는 PC | 쌓인 결과 조회·판정은 가능, 새로 읽기만 불가. (대안: 서버 OCR 서비스 — 유료라 보류) |
| 사내 라벨 문구가 DB에 저장됨 | AI 검사가 이미 같은 수준으로 저장 중. 파일 원본은 올리지 않음. RLS: 로그인한 사내 계정만 읽기 |

## 9. 먼저 정할 것

1. **DB 테이블 만들기**: 마이그레이션 SQL은 관리자가 Supabase SQL Editor에서 실행(운영 DB 변경).
2. **카테고리 기준**: 폴더 이름(`BOX 정리`/`스티커`/`멸균지 정리`)으로 자동 분류해도 되는지.
3. **처음 적재 범위**: 박스·스티커·멸균지 702개부터 시작하고, 리플렛 등은 이후 추가.
